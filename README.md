# chords_push — схемы аккордов на сетке Ableton Push

Кидаешь последовательность аккордов текстом — получаешь страницу со схемами:
одна схема = один аккорд, на всё той же сетке Push.

```bash
python3 song.py "Bb Bbmaj7b5 Gm Gm6 Dsus2 Dm Csus4 C Am" --name "Название песни"
# -> songs/nazvanie-pesni/index.html
```

Или кидаешь **страницу с подбором** (guitartuna, ultimate-guitar, amdm — любая):
я разбираю её в текстовый файл «аккорды над текстом», и получается страница
с текстом песни слева и схемами Push справа.

```bash
python3 songpage.py source.txt
# -> songs/unethical/index.html
```

А если задача обратная — **накликать пэды и узнать, что за аккорд получился** —
для этого есть локальное приложение:

```bash
python3 serve.py          # или двойной клик по start.command
# -> http://127.0.0.1:8765/ откроется в браузере
```

Модель зафиксирована: **Note / Chromatic, раскладка 4ths**, нижний левый пэд — C1.
Раскраска сетки тоже одна и та же — **тоника C + гамма C major**, Scale на железе
не переключается. Никакого In Key, никаких 3rds / Sequential.

## Схема: как читать

| цвет | что значит |
|---|---|
| **зелёный** | **рут аккорда** — всегда, в басе он или нет |
| голубой | остальные ноты выбранной аппликатуры |
| бледные зелёный / голубой | **обращения**: те же ноты на других пэдах и в других октавах |
| **фиолетовый** | нота, выделенная руками — **в аккорд не входит** |
| оранжевый | нота C — тоника раскраски сетки |
| белый | нота входит в гамму C major |
| тёмный | нота вне гаммы |

Рядом с именем ноты, помельче, стоит ступень: `Bb 1`, `D 3`, `F 5`. Раньше она стояла
под именем и упиралась в нижний край пэда — на 26px высоты две строки со скобками не
помещались. Сбоку места хватает, но впритык: худший случай — `Gb b13` у `7b13`, это 35px
при пэде 36px. Поэтому трёхсимвольные ступени (`bb7`, `b13`, `#11`) получают класс `l3`
и кегль на полпункта меньше, а `CARD_MIN` не опускается ниже 315.

Обращения показываются всегда, раскладка всегда компактная — переключателей для этого
нет и не нужно. Кнопки **S / M / L** меняют размер (кегль текста на странице песни,
ширину схем на странице `song.py`); всё резиновое, за край экрана ничего не уезжает.

## Схему можно переопределить руками

Солвер предлагает аппликатуру, но последнее слово за рукой:

| действие | что делает |
|---|---|
| клик по бледному пэду | переносит голос той же ноты на этот пэд |
| ...если при этом сменился бас | схема подписывает, какое вышло обращение |
| клик по любому другому пэду | добавляет ноту **не из аккорда** — фиолетовым |
| клик по ней ещё раз | снимает |
| **⟲** | возвращает аппликатуру солвера и убирает всё лишнее |

Выделить можно любую ноту на гриде, не только аккордовую. Рядом подписывается её
ступень относительно рута аккорда (`b2`, `7`, `#4`), рамка не белая, а фиолетовая —
сразу видно, что нота добавлена рукой. Какой аккорд из этого получился, страница
не гадает и не переименовывает: это просто подсветка.

У изменённой схемы появляется **маленькая зелёная точка** у имени аккорда, кнопка сброса
и подпись обращения; строка ступеней пересчитывается на лету. **Правки живут до
перезагрузки страницы** — никуда не сохраняются.

Запрет на обращения — это правило **солвера**, а не страницы: сам он бас по-прежнему
не трогает и подписывать ему нечего. Подпись появляется ровно тогда, когда бас
переставили руками.

Схемы рисуются **HTML'ом**, а не SVG, по двум причинам. Первая: в SVG текст живёт внутри
`viewBox` и уменьшается вместе с картинкой — на узкой колонке имя ноты падало до 7px.
В HTML размер задан через `clamp()` и упирается в пол: схема может быть мелкой, а буквы
читаемыми. Вторая: по HTML-пэду можно кликнуть. SVG остался форматом **экспорта** —
флаг `--svg` кладёт картинки в `songs/<slug>/svg/`.

## Плотность: все схемы песни на одном экране

Схема занимает **315–330px** (`CARD_MIN` / `CARD_MAX` в `songpage.py`) вместо прежних 380,
и на ноутбучном экране видны сразу все аккорды песни — раньше помещался один. Что для
этого сделано, по убыванию выигрыша:

* **кегль отвязан от ширины схемы.** Раньше он был `clamp(...,3.1cqw,15px)` и падал
  вместе с пэдом, поэтому «сжать схему» автоматически значило «уменьшить текст». Теперь
  имя ноты 14px, ступень 9px рядом с ним;
* **обвязка сведена к одной строке.** Шапка со схемой, подпись со ступенями, рамка
  карточки и её отступы занимали 94px при сетке 205px — треть площади. Теперь имя
  аккорда, ноты и ступени стоят в одну строку под сеткой, а карточки-обёртки нет вовсе;
* **вторая раскладка убрана.** Широкая (некомпактная) схема больше не рендерится —
  страница похудела вдвое, с 79KB до 51KB.

`CARD_MAX` нужен не меньше, чем `CARD_MIN`: без потолка одинокая колонка растягивает
схему на весь сайдбар, схема становится выше — и в экран перестаёт влезать следующий ряд.

Подпись под сеткой умеет **переноситься**, и обе её половины умеют сжиматься. Это не
косметика: с `white-space:nowrap` аккорд, у которого руками выделен десяток нот, распирал
строку ступеней, та распирала карточку — и карточка выезжала за свою колонку, наезжая
именем аккорда на подпись. Плюс у добавленных руками нот повторяющиеся ступени в списке
схлопываются: одна и та же нота в двух октавах даёт одну ступень.

## Компактные аккорды

Рука берёт аккорд поперёк грида, поэтому важна **ширина фигуры в колонках**, а не
её высота. Раньше солвер жал фигуру по рядам и спокойно раскидывал `Bb` на пять
колонок — играть такое неудобно. Теперь фигура всегда держится в **четырёх колонках**;
выключателя нет, потому что широкая раскладка не нужна никогда.

```
Bb, широко (5 колонок)        Bb, компактно (4 колонки)
r4c2 · r4c6 · r5c4            r4c2 · r5c1 · r5c4
```

Потолок и веса — в `push_grid.json` → `voice_leading.compact_mode`
(правки вносить в `build_json.py`):

| ключ | что делает |
|---|---|
| `max_cols` | потолок занятых колонок, сейчас **4** |
| `relax_cols` | если аккорд в потолок не лезет — отпускаем по шагам 5, 6, 7, 8 |
| `col_weight` / `row_weight` | в компактном режиме колонка стоит 3, ряд 1; в обычном наоборот |

Физика простая: интервал `n` ложится на грид векторами `(dr, dc)` с `n = 5*dr + dc`,
поэтому **трезвучие уже четырёх колонок не бывает** — квинта даёт `dc = 2`, терция
`dc = −1`, вот и четыре. А `sus2`, `sus4`, `7sus4`, `aug`, `7b5` ложатся в три.
Единственный тип, которому четырёх мало, — шестинотный `min13`; ему потолок
отпускается до пяти.

Ещё уже было бы можно, но только сменой баса: первое обращение мажорного трезвучия
садится в три колонки. Обращения в проекте запрещены осознанно (см. ниже), поэтому
компактный режим до них не опускается.

## Голосоведение

Аппликатуры подбираются **не для каждого аккорда по отдельности, а сразу для всей
цепочки**. Одна и та же гармония ложится на грид десятками способов — разные обращения,
разные октавы, и для каждой ноты несколько пэдов, — поэтому есть из чего выбирать.

**Структура аккорда при этом неприкосновенна.** Обращения солверу запрещены:
рут всегда остаётся в басу, набор интервалов — ровно тот, что записан в символе.
Менять бас ради удобства руки — значит подменять гармонию, а этого мы не делаем.
Свободы всё равно достаточно: выбор октавы плюс выбор пэда для каждой ноты
(на гриде одна нота лежит на нескольких пэдах — см. §3.2 `GRID_SPEC.md`).

Солвер считает динамическое программирование по всей последовательности:

* **цена узла** — габарит фигуры + насколько она далеко от середины грида;
* **цена перехода** — движение голосов в полутонах + сдвиг центра фигуры по пэдам
  − премия за каждую ноту, которая остаётся на **том же самом пэде**.

Часть нот в итоге переходит из аккорда в аккорд не сходя с пэда — палец с них можно
не снимать. Отдельной пометки на схеме для этого нет: соседние схемы и так видно рядом.

Замер на шести разных последовательностях против независимого выбора:

| | было | стало |
|---|---|---|
| путь руки по гриду | 55.9 | **27.2** (−51%) |
| нот остаётся на месте | 19 | **32** (×1.7) |
| движение голосов, полутонов | 68.9 | **59.6** (−14%) |

Веса лежат в `push_grid.json` → `voice_leading.weights`, крутятся без правки кода.
Отключить голосоведение целиком: `--no-voice-leading`. Разрешить обращения
(строго для экспериментов — бас поедет): `--allow-inversions`.

## Страница песни: текст слева, схемы справа

`songpage.py` ест обычный «аккорды над текстом» — ровно то, что показывает любой
сайт с подборами. Источник разбирается руками (я), формат простой:

```
@title: Ð¤Ð¾Ð½Ð°ÑÐ¸
@artist: ÐÑÐ¾-ÑÐ¾
@key: Dm
@source: https://guitartuna.com/chords/...

# Intro
Bb        Bbmaj7b5

# Verse 1
Bb
Lanterns in the rain
Am                 C
Walk to the harbor
```

* `@ключ: значение` — шапка: `title`, `artist`, `key`, `bpm`, `capo`, `source`, `tuning`;
* `# Название` — секция;
* строка, все токены которой читаются как аккорды, — строка аккордов. Если следом
  идёт текст, аккорды встают **над своими слогами по колонкам**; если нет — это
  проигрыш;
* `.` в начале строки — «это точно аккорды», `|` — «это точно текст». Нужно редко.

**Схемы строятся только для аккордов, которые звучат под текстом.** Интро, аутро и
проигрыши остаются в тексте (бледным), но сайдбар ими не засоряется — `--all-chords`
снимает ограничение. Схема одна на уникальный аккорд, а аппликатура к ней выбирается
не в вакууме: солвер прогоняется по всей реальной цепочке песни, и карточке достаётся
тот вариант, который в этой цепочке встретился чаще всего.

```bash
python3 songpage.py source.txt                  # -> songs/<slug>/index.html
python3 songpage.py source.txt --name "Своё имя" --svg
python3 songpage.py source.txt --all-chords     # схемы и для интро тоже
```

**Страница целиком не скроллится.** Шапка (название, тональность, переключатели)
занимает одну строку и стоит намертво, а текст и схемы — две независимые области, каждая
со своим скроллом: листаешь схемы — текст не двигается, и наоборот. Раньше сайдбар был
`position:sticky` внутри общего скролла, и схемы не долистывались до конца, пока страница
не уедет вверх вместе с шапкой. Всё остальное — легенда, список схем, ссылка на источник,
пояснения — уехало в подвал текстовой колонки, чтобы не отъедать высоту.

Колонки поделены **пополам**, и между ними есть ручка: тянешь мышкой — граница едет,
двойной клик возвращает 50/50, стрелки ← → работают, если ручка в фокусе (Shift — шаг
крупнее). Утянуть сайдбар уже одной схемы ручка не даёт. Схемы встают в несколько колонок,
когда есть место: на ноутбучном экране это две колонки и вся песня целиком, без
прокрутки. На узком окне колонка остаётся одна — тогда ручка и пригождается. На телефоне
схемы превращаются в ленту с горизонтальной прокруткой над текстом. Кнопки **S / M / L**
меняют кегль текста (M — резиновый, по ширине окна).

## Как писать аккорды

Регистр значим — как в обычной нотации: `CM7` большой мажорный, `Cm7` малый минорный.

```
C  Cm  Cdim  Caug  Csus2  Csus4  C5  Csus4add9
C6  Cm6  C6/9  C6sus4
Cmaj7  Cm7  C7  CmMaj7  Cm7b5  Cdim7  Cdim(maj7)  Cmaj7b5  C7sus4  Cmaj7sus4
Cadd9  Cmadd11  Cmaj9  Cm9  C9  C7b9  C7#9  Cm7b9  CmMaj9  C9sus4  C7susb9
C9b5  C9#5  C7b9#5  C7#9#5
Cmaj11  Cm11  C11  Cm11b5  Cmaj7#11  Cmaj9#11  C9#11
C13  Cmaj13  Cm13  C13sus4  C13b9  C13#11  C7b13  C7b9b13  C7#9b13  C7alt
Am/C          — слэш-бас: аккорд Am, снизу C
C(b5)         — альтерация в скобках (голое 'Cb5' читается как квинта от Cb)
```

Разделители в последовательности любые: пробел, запятая, `|`, `->`.
Полный список написаний — в `push_grid.json` → `chord_aliases`.

**Таблица закрытая, и это осознанно** — генеративного парсера суффиксов нет.
Наткнулся на неизвестный аккорд: тип дописывается в `CHORDS` и алиасы в
`_ALIAS_PAIRS` внутри `build_json.py`, дальше `python3 build_json.py` и тесты.
Есть сторож: у двух разных типов не должно совпадать множество классов высот от
одного рута, иначе определитель будет предлагать два имени одному набору нот.

Чего в таблице нет намеренно: `Cadd13` и `Cmadd13` (по классам высот это ровно
`C6` и `Cm6` — второе имя тому же набору), `Cmaj13#11` (семь нот, а больше шести
на схеме не бывает), аккорды с одновременно альтерированными ноной и ундецимой
(`C7b9#11`, `C7#9#11`) — их территорию закрывает `C7alt`. У `C13#11` квинта
опущена: с ней вышло бы семь нот, а живой пианист в этом аккорде как раз квинту
и убирает.

## API

```python
from push_grid import Grid, voice_progression, voice_chord, render_chord_svg

svg = render_chord_svg("Bbmaj7b5")            # схема одного аккорда, сам по себе

g = Grid()
vs = voice_progression(g, ["Bb", "Gm", "Gm6", "Dm"])   # вся цепочка сразу
for v in vs:
    v.notes        # MIDI-ноты
    v.note_names   # ['G2', 'Bb2', 'D3', 'E3'] — с правильным написанием
    v.pads         # [(3, 4), (4, 2), (5, 1), (5, 3)] — выбранная аппликатура
    v.held         # пэды, остающиеся зажатыми с прошлого аккорда
    v.inversion    # номер обращения, 0 = основной вид
    v.move         # насколько сдвинулась рука
    v.ghosts       # остальные пэды тех же нот — другие обращения
    v.overlay      # {(r, c): PadMark(degree, is_root, ghost, held)}

g.midi(0, 0)     # 36
g.pads_of_midi(48)   # [(1, 7), (2, 2)] — одна нота лежит на нескольких пэдах
print(g.to_ascii("degree"))
```

## Модель в одну строку

```
midi(r, c) = 36 + 5*r + c
```

`r` — ряд снизу вверх (0..7), `c` — колонка слева направо (0..7). Отсюда:

* вправо на пэд → **+1 полутон**; вверх на ряд → **+5 полутонов** (кварта);
* `(+1, −5)` → **та же нота**; `(+2, +2)` → **октава**;
* сдвиг фигуры на `(dr, dc)` транспонирует все её ноты на `5*dr + dc` — **форма аккорда
  работает в любой точке грида** (гитара в чистом кварт-строе, без «излома» G–B);
* колонки 5–7 ряда `r` совпадают с колонками 0–2 ряда `r+1`; из 64 пэдов
  **43 уникальные высоты**, 21 пэд — повтор. Эти повторы и есть обращения на схеме.

Подробности и таблицы — в `GRID_SPEC.md`. Раскраска сверена с фотографией Push:
совпали все 64 пэда.

## Локальное приложение

`python3 serve.py` поднимает сервер на 127.0.0.1 (наружу ничего не торчит,
ставить нечего — всё из стандартной библиотеки). Три вещи:

* **главная** `/` — список песен из `songs/` и список подборов из `picks/`;
* **определение аккорда** `/find` — большая пустая сетка, кликается любой пэд.
  Что получилось, считает сервер и отвечает символом, ступенями и правильной
  записью нот. Ниже — подбор: последовательность, которую можно перетаскивать,
  править и сохранить под именем в `picks/<slug>.json`;
* **страницы песен** `/songs/<slug>/` — те же самые файлы, просто по http.

Почему питон, а не нода: сервер делает `import push_grid` и получает таблицу
65 типов, солвер и правописание нот даром. На ноде музыкальную теорию пришлось
бы держать второй копией — а в проекте ровно обратное правило.

**Как страницы устроены внутри.** Четыре страницы (песня, определение, главная,
голая цепочка аккордов) собираются из одной рамы — `webapp.py`: документ целиком
(`page`), шапка со ссылкой на главную (`header`), раскладка «две колонки с ручкой
между ними» (`layout_css` + `LAYOUT_JS` + `gutter`) и сетка карточек-схем
(`.cards`, пол и потолок ширины). Правило: понадобилось второй странице —
переезжает в `webapp.py`, а не копируется.

Схема — тоже одна сущность, но живёт она рядом со своим CSS, в `push_grid.py`:
`render_html` рисует готовую схему (питон знает аккорд), `render_card_template` —
ту же самую карточку пустой, чтобы подписи проставил JS (аккорд знает только
браузер). Пэд в обоих случаях рождается в одной функции `_pad_span`. Поэтому
схема в подборе — не иконка и не похожая картинка, а буквально та же карточка
того же размера, что схема в песне.

Раскраска везде одна и та же: **рут зелёный, остальные ноты аккорда голубые,
добавленное руками — фиолетовое**, бледные — те же ноты на других пэдах.

**Рут называет человек, а не алгоритм.** Первый нажатый пэд — рут: от него
страница и строит аккорд. Те же четыре ноты, начатые с A, — это `Am7`; начатые
с C — `C6/A`. Второй вариант никуда не девается, он в списке под разбором, и клик
по нему переносит рут на него: дальше аккорд строится уже оттуда. Если от
залоченного рута аккорда в таблице нет — страница так и говорит, а найденное от
других рутов кладёт в список вариантов; сам рут при этом никуда не уезжает.
Например `C C# E`: зелёным остаётся C, а `C#mMaj7/C` предлагается вариантом. Повторный клик
по рутовому пэду сбрасывает сетку целиком — аккорд читается заново, а не
пересчитывается на новый рут. Больше шести нот аккорд не берёт (шесть — самый
большой тип в таблице), после этого пэды принимают только снятие.

**Интервалы и ступени считаются по реальному расстоянию, а не по классам высот.**
C и D♭ октавой выше — это малая нона, а не малая секунда; пэд под курсором,
лежащий октавой выше рута, подписан `9`, а не `2`. Тот же принцип, что в таблице
аккордов, где `add9` хранится как 14, а не как 2. Таблица интервалов доходит до
терцдецимы (21 полутон), а сетка растягивается на 42 — дальше интервал называется
составным: «малая секунда через 2 октавы».

**Что считается совпадением.** Точное — классы высот выбранных нот в точности
равны классам аккорда. Послабления ровно два: одна лишняя нота сверх аккорда
(и только поверх аккорда от трёх нот), либо не хватает ровно квинты (и только
у аккордов от четырёх нот — пианист опускает квинту, но не терцию). Одновременно
«и не хватает, и лишняя» не бывает: так под любые четыре ноты подгонялась
половина таблицы. Если точное совпадение нашлось хоть одно — приблизительные не
показываются вовсе.

Требование «лишняя нота только поверх трезвучия» появилось не сразу: без него
три ноты F♯ B C объявлялись аккордом `B5/F#` — то есть назывались по двум нотам
из трёх, а третья объявлялась лишней. Теперь такой набор честно отвечает, что
аккорда в таблице нет, а F♯ B G — что это `Gmaj7` без квинты.

Подбор хранит **пэды, а не только символ**: иначе теряется аппликатура, которую
накликали руками. Файл `picks/<slug>.json` — обычный json, его видно в Finder.
Ступени и запись нот в файл не пишутся: это производное, `identify.enrich`
пересчитывает их при открытии подбора. Одно место правды вместо двух копий.
