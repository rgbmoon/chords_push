# chords_push — схемы аккордов на сетке Ableton Push

Вставляешь аккорды или текст песни с аккордами — получаешь схемы на сетке Push:
одна схема = один аккорд, аппликатуры подобраны сразу для всей цепочки.

Всё работает в браузере: сервера нет, разборы хранятся у тебя (IndexedDB).

* **последовательность** — `Bb Bbmaj7b5 Gm Gm6 Dsus2 Dm Csus4 C Am` → лента схем;
* **песня** — «аккорды над текстом», хоть сырой копипаст с ultimate-guitar или amdm →
  текст слева, схемы справа;
* **определение аккорда** (`/find`) — накликать пэды и узнать, что за аккорд получился,
  собрать из этого подбор.

Модель зафиксирована: **Note / Chromatic, раскладка 4ths**, нижний левый пэд — C1.
Раскраска сетки тоже одна и та же — **тоника C + гамма C major**, Scale на железе
не переключается. Никакого In Key, никаких 3rds / Sequential.

## Разработка

```bash
npm install
npm run dev       # http://localhost:5173
npm test          # паритет с Python-версией + инварианты + интерфейс
npm run build     # tsc + vite -> dist/
```

Сайт собирает Netlify из ветки `main` (`netlify.toml`): `npm run build`, папка `dist`,
любой адрес отдаёт `index.html` — маршруты разбирает react-router.

## Откуда взялся TypeScript

Раньше это был Python: CLI делал страницы, `serve.py` поднимал локальный сервер.
На Netlify Python не исполняется, поэтому ядро переписано на TypeScript и работает
в браузере. Python-версия лежит в первом коммите истории.

Правило «музыкальная теория живёт в одном месте» при этом не нарушено: копии
больше нет, а то, что TS считает ровно то же, что считал Python, проверяют
**эталоны**. Перед удалением Python прогнали на тысячах входов — все алиасы × все
тоники, все типы × 12 тоник, 264 случайные цепочки во всех режимах солвера, 526
наборов пэдов для определителя, тексты песен — и записали ответы в
`tests/fixtures/`. TS обязан ответить так же до символа, разметка схем сверяется
пэд в пэд, CSS — байт в байт.

Ловушки, на которых порт мог разойтись молча, и как они закрыты:

* ключи `"5" "6" "7" "9" "11" "13" "69"` в JS-объекте уезжают в начало — а от порядка
  таблицы зависит, какое имя определитель назовёт первым. Таблицы — массивы пар и `Map`;
* `%` и `//` на отрицательных: в JS остаток и усечение, в Python модуль и пол — `mod()`
  и `floorDiv()`;
* сортировка по ключу-кортежу и выбор первого из равных — `sortByKey`, `argMin`;
* пробелы: у Python в `str.split()` свой набор (есть `\x1c-\x1f`, нет `﻿`);
* колонки аккордов считаются в кодовых точках, а не в UTF-16 — эмодзи в тексте
  не сдвигают аккорд со слога.

## Ввод: что можно вставить

Одно поле на главной. Что это — последовательность или песня, решает приложение:
если после шапки, секций и пустых строк остались только строки аккордов — это
последовательность, иначе песня. Под полем сразу видно, что получится.

**Последовательность** — разделители любые: пробел, запятая, `|`, `->`.
Подряд идущие повторы схлопываются. Нераспознанный аккорд — ошибка со списком,
молча он не пропадёт.

**Песня** — обычный «аккорды над текстом»:

```
@title: Фонари
@artist: Кто-то
@key: Am

# Куплет 1
Am                F
Вечер тихо ходит по крыше
C                     G
Ветер пишет письма воде
```

* `@ключ: значение` — шапка: `title`, `artist`, `key`, `bpm`, `capo`, `source`, `tuning`;
* `# Название` — секция;
* строка, все токены которой читаются как аккорды, — строка аккордов. Если следом
  идёт текст, аккорды встают **над своими слогами по колонкам**; если нет — это
  проигрыш;
* `.` в начале строки — «это точно аккорды», `|` — «это точно текст». Нужно редко.

**Сырой копипаст** чистится сам, и ни один аккорд при этом не съезжает со слога:
лишнее заменяется пробелами той же ширины, а не вырезается.

| что было | что стало |
|---|---|
| `[Verse 1]`, `Припев:` на своей строке | секция |
| `Intro: Am F C G` | секция + строка аккордов |
| табы, неразрывные пробелы | пробелы (табы — по 8 колонок) |
| `E*`, `F*` | звёздочки-сноски срезаются |
| `A7 (E string - 3 1 0)` | пометки в скобках убираются; `C(b5)`, `Cm(maj7)` — нет |
| `x2`, `(x2)`, `N.C.`, `\| Am \| F \|` | шум, убирается |
| `H`, `Hm7` | `B`, `Bm7` |
| `Bm7-5`, `C+5` | `Bm7b5`, `C#5` |

Аккорд, которого нет в таблице, но который выглядит как аккорд (`Cmaj7#9`), не
превращает строку в текст: он виден в тексте фиолетовым, схемы не получает и
попадает в предупреждения. Обычные слова за аккорды не принимаются — «Bad», «Day»,
«Down» спотыкаются на строчных буквах.

**Схемы строятся только для аккордов, которые звучат под текстом.** Интро, аутро и
проигрыши остаются в тексте (бледным), но сайдбар ими не засоряется. Если под текстом
аккордов нет вовсе — схемы по всем. Схема одна на уникальный аккорд, а аппликатура к
ней выбирается не в вакууме: солвер прогоняется по всей реальной цепочке песни, и
карточке достаётся тот вариант, который в этой цепочке встретился чаще всего.

## Хранилище

Разборы и подборы лежат в IndexedDB этого браузера. В базе только выбор человека:
источник разбора и накликанные пэды, имя подбора и его пэды. Схемы, ступени и запись
нот — производное, оно пересчитывается при каждом открытии: солвер укладывается в
миллисекунды, а схемы никогда не разъедутся с текстом.

* После первого сохранения приложение просит `navigator.storage.persist()` — тогда
  браузер не очистит базу, даже если место на диске кончится. Статус и кнопка
  «попросить ещё раз» — внизу главной.
* **Бэкап** — там же: выгрузить всё в `chords-push-ГГГГ-ММ-ДД.json`, загрузить обратно.
  Загрузка сливает по id: из двух версий одной записи побеждает более свежая.
  Это же — способ перенести разборы на другое устройство.
* Если браузер хранилище не даёт вовсе, приложение не падает: держит всё в памяти
  вкладки и честно об этом пишет.

Всё, что приходит снаружи (из схемы, из файла бэкапа), проходит через чистильщики:
в базу попадают только пэды 0..63, строки обрезаются, мусор выбрасывается. Ссылка на
источник в разборе — только `http(s)`.

## Схема: как читать

| цвет | что значит |
|---|---|
| **зелёный** | **рут аккорда** — всегда, в басе он или нет |
| голубой | остальные ноты выбранной аппликатуры |
| бледные зелёный / голубой | **обращения**: те же ноты на других пэдах и в других октавах |
| **фиолетовый** | нота, выделенная руками — **в аккорд не входит** |
| оранжевый | нота C — тоника раскраски сетки |
| белый | нота входит в гамму C major |
| тёмный | нота вне гаммы |

Рядом с именем ноты, помельче, стоит ступень: `Bb 1`, `D 3`, `F 5`. Раньше она стояла
под именем и упиралась в нижний край пэда — на 26px высоты две строки со скобками не
помещались. Сбоку места хватает, но впритык: худший случай — `Gb b13` у `7b13`, это 35px
при пэде 36px. Поэтому трёхсимвольные ступени (`bb7`, `b13`, `#11`) получают класс `l3`
и кегль на полпункта меньше, а `CARD_MIN` не опускается ниже 315.

Обращения показываются всегда, раскладка всегда компактная — переключателей для этого
нет и не нужно. Кнопки **S / M / L** меняют размер (кегль текста на странице песни,
ширину схем на странице последовательности); всё резиновое, за край экрана ничего
не уезжает.

## Схему можно переопределить руками

Солвер предлагает аппликатуру, но последнее слово за рукой:

| действие | что делает |
|---|---|
| клик по бледному пэду | переносит голос той же ноты на этот пэд |
| ...если при этом сменился бас | схема подписывает, какое вышло обращение |
| клик по любому другому пэду | добавляет ноту **не из аккорда** — фиолетовым |
| клик по ней ещё раз | снимает |
| **⟲** | возвращает аппликатуру солвера и убирает всё лишнее |

У изменённой схемы появляется **маленькая зелёная точка** у имени аккорда, кнопка сброса
и подпись обращения; строка ступеней пересчитывается на лету. **Правки сохраняются
сразу по клику** — в хранилище браузера, с задержкой 120 мс, чтобы перенос голоса и
следующий клик легли одной записью. Вернул схему как было — запись удаляется, а не
копится. Ключ правки — символ аккорда на странице песни и «номер:символ» на странице
последовательности (там один аккорд может встретиться дважды, и схема у каждого места
своя). При открытии число нот сверяется: источник могли поменять под тем же именем.

Запрет на обращения — это правило **солвера**, а не страницы: сам он бас по-прежнему
не трогает и подписывать ему нечего. Подпись появляется ровно тогда, когда бас
переставили руками.

Схемы рисуются **HTML'ом**, а не SVG, по двум причинам. Первая: в SVG текст живёт внутри
`viewBox` и уменьшается вместе с картинкой — на узкой колонке имя ноты падало до 7px.
В HTML размер задан через `clamp()` и упирается в пол: схема может быть мелкой, а буквы
читаемыми. Вторая: по HTML-пэду можно кликнуть.

## Плотность: все схемы песни на одном экране

Схема занимает **315–330px** (`CARD_MIN` / `CARD_MAX` в `src/styles/css.ts`), и на
ноутбучном экране видны сразу все аккорды песни. Что для этого сделано, по убыванию
выигрыша:

* **кегль отвязан от ширины схемы.** Раньше он был `clamp(...,3.1cqw,15px)` и падал
  вместе с пэдом, поэтому «сжать схему» автоматически значило «уменьшить текст». Теперь
  имя ноты 14px, ступень 9px рядом с ним;
* **обвязка сведена к одной строке.** Имя аккорда, ноты и ступени стоят в одну строку
  над сеткой, а карточки-обёртки нет вовсе;
* **вторая раскладка убрана.** Широкая (некомпактная) схема больше не рендерится.

`CARD_MAX` нужен не меньше, чем `CARD_MIN`: без потолка одинокая колонка растягивает
схему на весь сайдбар, схема становится выше — и в экран перестаёт влезать следующий ряд.

Подпись умеет **переноситься**, и обе её половины умеют сжиматься. Это не
косметика: с `white-space:nowrap` аккорд, у которого руками выделен десяток нот, распирал
строку ступеней, та распирала карточку — и карточка выезжала за свою колонку. Плюс у
добавленных руками нот повторяющиеся ступени в списке схлопываются: одна и та же нота
в двух октавах даёт одну ступень.

## Компактные аккорды

Рука берёт аккорд поперёк грида, поэтому важна **ширина фигуры в колонках**, а не
её высота. Фигура всегда держится в **четырёх колонках**; выключателя нет, потому что
широкая раскладка не нужна никогда.

```
Bb, широко (5 колонок)        Bb, компактно (4 колонки)
r4c2 · r4c6 · r5c4            r4c2 · r5c1 · r5c4
```

Потолок и веса — в `src/core/data.ts` → `VOICE_LEADING.compact_mode`:

| ключ | что делает |
|---|---|
| `max_cols` | потолок занятых колонок, сейчас **4** |
| `relax_cols` | если аккорд в потолок не лезет — отпускаем по шагам 5, 6, 7, 8 |
| `col_weight` / `row_weight` | в компактном режиме колонка стоит 3, ряд 1; в обычном наоборот |

Физика простая: интервал `n` ложится на грид векторами `(dr, dc)` с `n = 5*dr + dc`,
поэтому **трезвучие уже четырёх колонок не бывает** — квинта даёт `dc = 2`, терция
`dc = −1`, вот и четыре. А `sus2`, `sus4`, `7sus4`, `aug`, `7b5` ложатся в три.
Шире четырёх раскладываются шесть типов, и все — в пять колонок: из пятинотных
`minMaj9` и `maj7#11`, из шестинотных `maj9#11`, `m11b5`, `min13` и `13b9`. Им потолок
отпускается, а не режет ноты; список держит тест поимённо, чтобы новый тип не попал
в него незаметно.

Ещё уже было бы можно, но только сменой баса: первое обращение мажорного трезвучия
садится в три колонки. Обращения в проекте запрещены осознанно (см. ниже), поэтому
компактный режим до них не опускается.

## Голосоведение

Аппликатуры подбираются **не для каждого аккорда по отдельности, а сразу для всей
цепочки**. Одна и та же гармония ложится на грид десятками способов — разные обращения,
разные октавы, и для каждой ноты несколько пэдов, — поэтому есть из чего выбирать.

**Структура аккорда при этом неприкосновенна.** Обращения солверу запрещены:
рут всегда остаётся в басу, набор интервалов — ровно тот, что записан в символе.
Менять бас ради удобства руки — значит подменять гармонию, а этого мы не делаем.
Свободы всё равно достаточно: выбор октавы плюс выбор пэда для каждой ноты
(на гриде одна нота лежит на нескольких пэдах — см. §3.2 `GRID_SPEC.md`).

Солвер считает динамическое программирование по всей последовательности:

* **цена узла** — габарит фигуры + насколько она далеко от середины грида;
* **цена перехода** — движение голосов в полутонах + сдвиг центра фигуры по пэдам
  − премия за каждую ноту, которая остаётся на **том же самом пэде**.

Часть нот в итоге переходит из аккорда в аккорд не сходя с пэда — палец с них можно
не снимать.

Замер на шести разных последовательностях против независимого выбора:

| | было | стало |
|---|---|---|
| путь руки по гриду | 55.9 | **27.2** (−51%) |
| нот остаётся на месте | 19 | **32** (×1.7) |
| движение голосов, полутонов | 68.9 | **59.6** (−14%) |

Веса лежат в `src/core/data.ts` → `VOICE_LEADING.weights`. Тест
`tests/invariants.test.ts` держит этот выигрыш: путь руки обязан сокращаться минимум
на 30%, общих нот — расти минимум в 1.4 раза.

## Страница песни: текст слева, схемы справа

**Страница целиком не скроллится.** Шапка (название, тональность, переключатели)
занимает одну строку и стоит намертво, а текст и схемы — две независимые области, каждая
со своим скроллом: листаешь схемы — текст не двигается, и наоборот. Легенда, список схем,
ссылка на источник, пояснения — в подвале текстовой колонки, чтобы не отъедать высоту.

Колонки поделены **пополам**, и между ними есть ручка: тянешь мышкой — граница едет,
двойной клик возвращает 50/50, стрелки ← → работают, если ручка в фокусе (Shift — шаг
крупнее). Утянуть сайдбар уже одной схемы ручка не даёт. Схемы встают в несколько колонок,
когда есть место: на ноутбучном экране это две колонки и вся песня целиком, без
прокрутки. На телефоне схемы превращаются в ленту с горизонтальной прокруткой над текстом.

## Определение аккорда

`/find` — большая пустая сетка, кликается любой пэд. Что получилось, считает
`identify()` прямо в браузере и отвечает символом, ступенями и правильной записью нот.
Справа — подбор: последовательность, которую можно перетаскивать, править и сохранить
под именем.

**Рут называет человек, а не алгоритм.** Первый нажатый пэд — рут: от него
страница и строит аккорд. Те же четыре ноты, начатые с A, — это `Am7`; начатые
с C — `C6/A`. Второй вариант никуда не девается, он в списке под разбором, и клик
по нему переносит рут на него. Если от залоченного рута аккорда в таблице нет —
страница так и говорит, а найденное от других рутов кладёт в список вариантов; сам
рут при этом никуда не уезжает. Например `C C# E`: зелёным остаётся C, а
`C#mMaj7/C` предлагается вариантом. Повторный клик по рутовому пэду сбрасывает сетку
целиком. Больше шести нот аккорд не берёт (шесть — самый большой тип в таблице),
после этого пэды принимают только снятие.

**Интервалы и ступени считаются по реальному расстоянию, а не по классам высот.**
C и D♭ октавой выше — это малая нона, а не малая секунда; пэд под курсором,
лежащий октавой выше рута, подписан `9`, а не `2`. Таблица интервалов доходит до
терцдецимы (21 полутон), а сетка растягивается на 42 — дальше интервал называется
составным: «малая секунда через 2 октавы».

**Что считается совпадением.** Точное — классы высот выбранных нот в точности
равны классам аккорда. Послабления ровно два: одна лишняя нота сверх аккорда
(и только поверх аккорда от трёх нот), либо не хватает ровно квинты (и только
у аккордов от четырёх нот — пианист опускает квинту, но не терцию). Одновременно
«и не хватает, и лишняя» не бывает. Если точное совпадение нашлось хоть одно —
приблизительные не показываются вовсе.

Подбор хранит **пэды, а не только символ**: иначе теряется аппликатура, которую
накликали руками, — и какой пэд был рутом. Ступени и запись нот в базу не пишутся:
`enrich()` пересчитывает их при открытии подбора. Одно место правды вместо двух копий.

## Как писать аккорды

Регистр значим — как в обычной нотации: `CM7` большой мажорный, `Cm7` малый минорный.

```
C  Cm  Cdim  Caug  Csus2  Csus4  C5  Csus4add9
C6  Cm6  C6/9  C6sus4
Cmaj7  Cm7  C7  CmMaj7  Cm7b5  Cdim7  Cdim(maj7)  Cmaj7b5  C7sus4  Cmaj7sus4
Cadd9  Cmadd11  Cmaj9  Cm9  C9  C7b9  C7#9  Cm7b9  CmMaj9  C9sus4  C7susb9
C9b5  C9#5  C7b9#5  C7#9#5
Cmaj11  Cm11  C11  Cm11b5  Cmaj7#11  Cmaj9#11  C9#11
C13  Cmaj13  Cm13  C13sus4  C13b9  C13#11  C7b13  C7b9b13  C7#9b13  C7alt
Am/C          — слэш-бас: аккорд Am, снизу C
C(b5)         — альтерация в скобках (голое 'Cb5' читается как квинта от Cb)
```

Полный список написаний — в `src/core/data.ts` → `ALIAS_PAIRS`.

**Таблица закрытая, и это осознанно** — генеративного парсера суффиксов нет.
Наткнулся на неизвестный аккорд: тип дописывается в `CHORD_ROWS`, алиасы — в
`ALIAS_PAIRS` (оба в `src/core/data.ts`), дальше `npm test`. Есть сторож: у двух
разных типов не должно совпадать множество классов высот от одного рута, иначе
определитель будет предлагать два имени одному набору нот.

Чего в таблице нет намеренно: `Cadd13` и `Cmadd13` (по классам высот это ровно
`C6` и `Cm6` — второе имя тому же набору), `Cmaj13#11` (семь нот, а больше шести
на схеме не бывает), аккорды с одновременно альтерированными ноной и ундецимой
(`C7b9#11`, `C7#9#11`) — их территорию закрывает `C7alt`. У `C13#11` квинта
опущена: с ней вышло бы семь нот, а живой пианист в этом аккорде как раз квинту
и убирает.

> Таблица теперь меняется в TS, а эталоны в `tests/fixtures/` сняты со старой
> таблицы. Новый тип или алиас паритетные тесты на нём заметят — это ожидаемо:
> поправь эталон осознанно, а не молча.

## Модель в одну строку

```
midi(r, c) = 36 + 5*r + c
```

`r` — ряд снизу вверх (0..7), `c` — колонка слева направо (0..7). Отсюда:

* вправо на пэд → **+1 полутон**; вверх на ряд → **+5 полутонов** (кварта);
* `(+1, −5)` → **та же нота**; `(+2, +2)` → **октава**;
* сдвиг фигуры на `(dr, dc)` транспонирует все её ноты на `5*dr + dc` — **форма аккорда
  работает в любой точке грида** (гитара в чистом кварт-строе, без «излома» G–B);
* колонки 5–7 ряда `r` совпадают с колонками 0–2 ряда `r+1`; из 64 пэдов
  **43 уникальные высоты**, 21 пэд — повтор. Эти повторы и есть обращения на схеме.

В ядре пэд — это его номер `r*8 + c`. Подробности и таблицы — в `GRID_SPEC.md`.
Раскраска сверена с фотографией Push: совпали все 64 пэда (`tests/invariants.test.ts`).
